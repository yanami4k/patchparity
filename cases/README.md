# cases —— 改动用例

每个用例是一份 unified diff，施加在被测样例的玩法源码上。用例只允许触及玩法源码
（`Samples/Brawler/Assets/Brawler/`），不得包含工程环境的漂移（编辑器版本、包清单、脚本后端等），
否则两条验证路线的差异会混进与改动无关的因素。生成时去掉 diff 的 `index` 行，
它指向上游仓库的 blob 号，对复现无用且会随上游漂移。

用例按预期结论分三类：

- **安全**：补丁后行为应与整包重编逐帧一致。
- **危险**：补丁后行为应不一致，或补丁根本无法加载；工具应指出首个分歧 tick 与所属组件或系统。
- **边界**：结论以实测行为为准，用例里注明实测所得而非主观预期。

## 施加与撤销

```
git -C vendor/Klotho apply cases/<名字>.patch
git -C vendor/Klotho apply -R cases/<名字>.patch
```

## 一条硬约束

用例必须被验证场景覆盖到。改动点未被执行时两路必然一致，这种"一致"是假阳性，
不构成补丁等价的证据。每个用例都要记录其覆盖证据。
