# 场景搜索题集报告（2026-10-12）

S5 的 13 道题都在默认场景里验证。默认场景里角色移动速度为 0、场地没有地面，大量玩法代码根本不执行；改动落在这些代码上时，
补丁与整包重编"一致"，只是因为两边都没跑到改动。本轮新增 5 道场景搜索题：改动在默认场景里不执行，Agent 须先构造出能让
改动**可观测**的场景，再在该场景下完成等价性验证。

- 环境：阿里云香港 Windows Server 2022，8 vCPU 32 GiB；Unity 6000.3.18f1，HybridCLR v8.14.1；Pigeon `65ff318`；模型 DeepSeek `deepseek-v4-flash`。
- 可观测：同一场景下，整包重编与未打补丁的母包逐帧不同，说明改动真的被执行到了。场景搜索题要求可观测（`--require-observable`），
  不可观测即判作废；其余题目只把它作为覆盖强度报告。
- 题目与预期：`cases/cases.json`；实测依据：`cases/用例与实测结论.md`。

## 结果

**最终一轮（每题隔离、修复全部到位）5/5 判对，每道题都是第一次尝试就找到了可观测的场景。**
此前两轮各暴露出一个问题：第一轮工具说明里的示例泄了题，第二轮 judge 的取证规则在 Agent 多跑一次时失效。详见下文。

### 标准答案：命令行逐题实测（不经 Agent）

每道题在默认场景与手工构造的探测场景下各跑一次完整验证。

| 题目 | 类别 | 默认场景 | 探测场景 |
|---|---|---|---|
| search-safe-jump-speed | 安全 | 等价，不可观测 | 等价，可观测 |
| search-safe-move-formula | 安全 | 等价，不可观测 | 等价，可观测 |
| search-safe-hit-reaction | 安全 | 等价，不可观测 | 等价，可观测 |
| search-danger-curve | 危险 | **等价（假阴性）**，不可观测 | **不等价**：tick 2，Transform、PhysicsBody |
| search-danger-raycast | 危险 | **等价（假阴性）**，不可观测 | **不等价**：tick 2，PhysicsBody、Character |

两道危险题改的都是母包里的框架代码（击退衰减曲线的插值、静态射线检测的命中点），补丁带不过去，整包重编却生效。
在默认场景下它们被判为"等价"；没有可观测性检验，这两个危险改动会被当作安全放过。

### 第一轮：示例泄题

`list_scenarios` 的参数说明末尾有一行示例 `ground=1;moveSpeed=5;spawn=-1:0,1:0;attack=500;chase=1`，那正是手工构造的"打架"
探测场景，能让 5 道题同时可观测。Agent 第一步读了说明，3 道题原样照抄，另一道只删了出生位置。全部第一次尝试就"找到"，
场景搜索本身没被考到。示例改为只演示写法的 `seed=7;ticks=300;players=3`，并加一条测试：说明里不得出现地面、移动、攻击、
跳跃、出生位置、追逐这些参数（`fa63cd2`）。

### 第二轮：judge 取证规则在 Agent 多跑时失效

示例换掉之后，Agent 改为自己读 diff 推理。曲线一题的推理大意是：改动在击退曲线上，要让角色被打中，得有地面、移动速度、
攻击与追逐。它取的移动速度是 8，没给出生位置，首个分歧落在 tick 31（探测场景两人贴身出生，是 tick 2）。

射线一题判分失败。台账显示它在 `ground=1;moveSpeed=6` 下跑完了全部规定步骤，之后又换了一个场景补跑一次补丁。judge 以
"最后一次补丁运行的场景"取证，取到了只跑过一次补丁的那个场景，判为证据不全。规则改为取**确定性自检最晚完成的场景**
（同场景第二次补丁运行最晚的那个），没有场景跑过两次补丁时才退回原规则（`6fdb654`）。用修复后的 judge 重判第二轮存档的
5 份台账，全部符合预期，射线一题判为不等价、tick 2、PhysicsBody 与 Character，与命令行实测一致；经 Pigeon 重跑也通过。

审计第二轮的会话还发现两件事：

1. **compare_runs 的反馈误导 Agent**。一个 Agent 把系统名 `PlatformerCommandSystem` 填进了 `touched_components`，覆盖自检静默不过，
   连得三次"作废"，返回里只写"覆盖自检 不通过"。另外，判定为 divergent 时工具标记为出错：场景搜索时母包与整包重编 divergent
   恰恰是"找到了"，Agent 看到的却是"工具返回错误"，eval 的出错统计也几乎全是这一项。现在不认识的组件名直接拒绝并列出可用的
   组件，覆盖自检不过时说明是哪个组件没出现，比对做完了就不算出错（`0c25a55`）。
2. **跨题检索会话**。上面那个 Agent 为弄懂"作废"，调用了 Pigeon 内置的 `search_sessions` 与 `read_session_entry`，读到了同一输出
   目录里前一题的会话。按调用顺序，它在第 8 次工具调用时就定下了场景，第 20 次才去检索，这次没有影响结果；但通道是通的：场景搜索题里，
   前一题找到的场景正是后一题的答案。Pigeon 的 eval 模式无法从配置关掉这两个工具，patchparity 一侧以每题单独一个输出目录规避
   （`run-eval.ps1 -Isolate`，`5949d2d`）。Pigeon 之后的版本已移除这个跑题器。

## 由题集得出的认识

- **默认场景下的"等价"可能是空的，危险改动也会被判成等价**。可观测性检验把这种假阴性识别为"不可观测"；只有在可观测的场景下
  得出的结论才能当证据。
- **在给出 diff 和默认场景缺什么之后，构造场景对 Agent 并不难**：最终一轮 5 道题全部一次命中。这批题偏容易：题面交代了默认场景
  没有地面、移动速度为 0，参数空间也粗（地面、速度、职业、出生位置、按键频率、追逐）。需要多步前置条件（特定职业的技能、
  道具拾取、对局结束结算）的改动才会真正考验搜索，留待后续。
- **评测本身的漏洞比被测对象的漏洞更隐蔽**：示例泄题、取证规则不稳、工具反馈误导、跨题检索，四个问题都是看 Agent 的完整过程、
  而不是只看判分才发现的。第一轮 5/5 的成绩恰恰是最不可信的一轮。
- **判定不采信 Agent**：第二轮有 Agent 把 divergent 读成"完全相同"，结论里说错了，判分依然正确，因为 judge 只看服务端台账。

## 其他

- 验证载体新增了场景参数。缺省参数下随机数抽取顺序不变：用新旧两个母包在默认场景下各跑一次，逐 tick 哈希文件逐字节相同
  （末帧哈希 1154399133859401978，与路线图 S3 记录的基线一致），S5 的结论不受影响。
- 实测中修掉的问题：实测脚本 `Start-Process -Wait` 等整棵进程树，被 Unity 拉起的 .NET 编译服务器白等约十分钟（`81097d6`）；
  验证包的引擎启动日志混进命令行输出、把结论淹没，现改为写进各次运行的目录（`43a7a69`）。
- 五次 Pigeon 实跑（含重跑与终版构建核验）合计模型花费约 0.036 美元。

## 补记：换跑题器后的复验（同日）

Pigeon 之后的版本移除了 `pigeon eval`，跑题改由 patchparity 自己的 `patchparity eval`：每道题一个独立的工作目录，经 `pigeon run`（Pigeon `5e70ca2`）
起 Agent，关掉会话检索、联网与派 worker，收工后在同一目录跑验证脚本。用它重跑这 5 道题：

| 批次 | 跑题器 | 思考 | 判分 | 每题轮次 | token | 花费 | 墙钟 |
|---|---|---|---|---|---|---|---|
| `s6d`（上文最终一轮） | `pigeon eval`（65ff318） | 关 | 5/5 | 21/21/20/21/27 | 64.7 万 | 0.0093 美元 | 4.4 分 |
| `s7b` | `patchparity eval`（5e70ca2） | 关 | 5/5 | 21/19/19/25/21 | 91.2 万 | 0.0104 美元 | 4.5 分 |
| `s7` | `patchparity eval`（5e70ca2） | high | 5/5 | 23/19/20/20/22 | 99.3 万 | 0.0158 美元 | 6.4 分 |

（每题轮次按 jump-speed、move-formula、hit-reaction、danger-curve、danger-raycast 排列。）

- 新跑题器在相同模型与思考档位下复现了结果：5/5，每题第一次尝试即找到可观测的场景，判定、可观测性与危险题的分歧层与此前一致，
  只调用了 patchparity 的工具。token 多出约四成，来自新版 Pigeon 每次开跑附上的状态说明，多为缓存命中，花费只多一成。
- 第一批 `s7` 没有指定思考档位，新版 Pigeon 对 `deepseek-v4-flash` 默认取 high，而 S5、S6 都是关着跑的。判分同样 5/5，但花费高出五成，
  Agent 构造的场景也更"用力"（攻击概率拉满、指定职业）。跑题器因此加了 `--thinking`，`run-eval.ps1` 缺省关闭，新批次与既往结果同条件可比。
